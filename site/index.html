open-entity-gateway

Bridges between the goat fabric and vendor systems.

Each bridge is its own package that speaks one vendor's software kit: Anduril Lattice and Picogrid ECN today. A mapping file says how a record becomes a track; the bridge sends it in the vendor's form.

What it is

Tracks on the goat fabric reach outside systems three ways. This repository is the way for systems reached through a vendor's own software kit.

One package per vendor

A bridge lives in vendors/<vendor>/ with its own pyproject.toml, tests and README. It implements the adapter interface and imports its vendor's SDK, which the user installs under the vendor's license.

A mapping file per message

A YAML file matches one message type and says which fields are the identity, the position and the time, with one block per adapter. Every example address in the repository is a documentation address.

Open standards go elsewhere

TAK servers over Cursor on Target, SAPIENT controllers and ASTERIX consumers are reached through goat-transformers, as goatcore ADR 1255 sets out.

What is here, and what is moving

The repository began as a general gateway with its own track model, encoders and senders for open standards. Those parts duplicate goat-transformers and are moving there. Each keeps working until goat-transformers passes the same end-to-end test.

Run a bridge

Python 3.11 or later. A configuration names each destination; there is no default. The zenoh command subscribes only to the key expressions given with --key and refuses a key made only of wildcards.

python -m venv .venv && . .venv/bin/activate
pip install --require-hashes -r requirements/runtime.txt
pip install --no-deps -e . -e vendors/picogrid-ecn     # or vendors/lattice; then install that vendor's SDK
open-entity-gateway check --config gateway.yml
open-entity-gateway zenoh --config gateway.yml --zenoh-config fabric.json5 --key 'sensors/*/tracks'
